# 한국어 PR 템플릿

한국 프로젝트(팀원·리뷰어가 한국어를 쓰는 저장소)에 사용한다. 리뷰어가 diff를 열기 전에 의도와 확인 방법을 알 수 있게 쓴다.

## 작성 가이드

- **개요**: 이 PR이 무엇을, 왜 하는지 1~3문장. 본문만 읽어도 의도가 보여야 한다.
- **변경 사항**: 동작 변화를 영역별로 묶어 목록으로. 파일 나열이 아니라 *무엇이 바뀌었는지*를 쓴다. 호환성이 깨지는 변경은 따로 명시한다.
- **변경 이유**: 배경이 된 문제나 요구. 관련 이슈가 있으면 연결한다.
- **테스트**: 실제로 실행한 명령과 결과, 리뷰어가 따라 할 수 있는 수동 확인 절차. 실행하지 않은 테스트를 통과했다고 쓰지 않는다. 대신 "로컬 테스트 미실행"이라고 쓴다.
- **스크린샷**: 화면이 바뀐 경우에만. 아니면 섹션을 지운다.
- **체크리스트**: 실제로 확인한 항목만 `[x]`로 체크한다.
- **관련 이슈**: `Closes #123` / `Refs #123` 형식. 없으면 "없음".
- 목록 항목은 간결한 명사형으로 끝낸다(예: "쿠폰 할인 계산 함수 추가", "만료 쿠폰 에러 메시지 수정"). 이모지와 과장된 표현은 쓰지 않는다. 코드·명령·식별자는 원문 그대로 백틱으로 감싼다.

## 템플릿

```markdown
## 개요

<무엇을, 왜 하는지 1~3문장>

## 변경 사항

- <변경 1>
- <변경 2>

## 변경 이유

<해결하려는 문제나 요구>

## 테스트

- [ ] `<명령>` — <결과>
- <리뷰어용 수동 확인 절차>

## 스크린샷

<변경 전 / 후, 화면 변경이 있을 때만>

## 체크리스트

- [ ] 변경된 동작에 대한 테스트 추가·수정
- [ ] 기존 테스트 로컬 통과
- [ ] 동작·사용법이 바뀐 경우 문서 반영
- [ ] 호환성을 깨는 변경 없음 (있다면 위에 설명)

## 관련 이슈

<Closes #123 | 없음>
```
